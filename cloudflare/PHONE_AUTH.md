# Вход по номеру телефона

В профиле доступны регистрация и восстановление пароля через Telegram-бота: номер → открыть бота → поделиться собственным контактом → шестизначный код в чате → задать пароль. Дальнейший вход возможен по номеру или подтверждённому `@имени` Telegram и паролю. Повторное подтверждение того же номера открывает существующий аккаунт и позволяет сменить пароль. Имя аккаунта при этом не перезаписывается. Telegram Mini App остаётся отдельным способом входа; аккаунты не объединяются автоматически.

Бот не может найти человека и первым написать ему только по номеру. Контакт должен быть отправлен самим пользователем через кнопку бота; сервер проверяет `contact.user_id`, совпадение номера и одноразовый код. Используется обычный Bot API, без платного Telegram Gateway. WhatsApp в этот сценарий не входит.

## Подключение Telegram-бота

1. Примените миграции `0013_phone_accounts.sql`, `0014_telegram_code_login.sql` и `0015_account_passwords.sql`: `npm run db:migrate:remote`.
2. В Cloudflare Worker задайте секреты `BOT_TOKEN`, `AUTH_SECRET` (случайная строка длиной от 32 символов) и `TELEGRAM_AUTH_WEBHOOK_SECRET` (случайная строка из 32–256 латинских букв, цифр, `_` и `-`). `TELEGRAM_BOT_USERNAME` должен совпадать с именем бота без `@`.
3. Опубликуйте Worker и установите webhook бота на `https://<адрес Worker>/api/auth/telegram/webhook` вызовом Telegram Bot API `setWebhook`; параметр `secret_token` должен совпадать с `TELEGRAM_AUTH_WEBHOOK_SECRET`, а `allowed_updates` должен содержать `message`. Проверить регистрацию можно через `getWebhookInfo`. У одного бота может быть только один webhook: если он уже используется, передайте обновления входа в этот Worker из существующего обработчика либо объедините обработчики.

`AUTH_SECRET` участвует в определении аккаунта по номеру. Сохраняйте его постоянным: смена без миграции разорвёт соответствие существующих номеров аккаунтам. Полный номер не хранится в D1 и не возвращается клиенту.

Пароли хранятся только как PBKDF2-SHA-256 с индивидуальной случайной солью и секретом Worker. Пароль не записывается в журнал и не возвращается клиенту. Если `@имя` Telegram отсутствует или изменилось, вход по номеру остаётся доступным. Вход по паролю не требует открытия бота; бот нужен для регистрации и восстановления.

## Необязательный платный SMS-канал

Следующие инструкции описывают альтернативный SMS-вход. Он выключен, пока `SMS_LOGIN_ENABLED` не равен `true`, и не используется текущим интерфейсом.

Для доставки SMS-кодов используется [SMS.ru](https://sms.ru/docs/api/api_group_sms/send). До настройки сервиса SMS API сообщает, что вход недоступен. Демонстрационные коды, отправка кода в ответе API и обход подтверждения отсутствуют.

## Подключение

1. Получите API ID в SMS.ru, настройте отправителя и пополните баланс сервиса. При необходимости согласуйте шаблон текста `Вордик: код входа 123456. Никому его не сообщайте.`
2. Примените миграцию `0013_phone_accounts.sql` к D1: `npm run db:migrate:remote`. Для разработки используйте `npm run db:migrate:local`.
3. Задайте секрет `SMSRU_API_ID` и обычную переменную `SMS_LOGIN_ENABLED=true`. `AUTH_SECRET` уже нужен Telegram-входу. Секреты не должны попадать в Git или клиентские файлы.
4. При необходимости задайте обычные переменные `SMSRU_SENDER` (согласованный отправитель), `SMS_ALLOWED_COUNTRY_CODES` (по умолчанию `7`, несколько кодов через запятую), `SMS_DAILY_LIMIT` (по умолчанию 100, верхняя граница 1000).
5. Опубликуйте Worker и статические файлы. `account.js` включён в сборку Cloudflare. Для фронтенда на другом домене его origin должен входить в `ALLOWED_ORIGINS`; текущий GitHub Pages origin уже указан. API разрешает заголовок `Authorization`.

`AUTH_SECRET` участвует в определении аккаунта по номеру. Сохраняйте его постоянным: произвольная замена разорвёт соответствие существующих номеров аккаунтам. Не меняйте его без отдельной процедуры миграции.

Локально задайте эти значения в игнорируемом Git файле `.dev.vars` по образцу `.dev.vars.example` и запускайте приложение через Wrangler. На `localhost` и `127.0.0.1` клиент использует локальный API. Резервный `server.mjs` SMS-вход не обслуживает.

## Сессии и данные

Сервер выдаёт случайный непрозрачный токен на 30 дней, хранит только его SHA-256 и проверяет его в каждом запросе рейтинга, друзей и игр. Браузер передаёт токен в `Authorization: Bearer`, что работает и для существующего фронтенда GitHub Pages без зависимости от сторонних cookies. Токен хранится в localStorage; новые сторонние скрипты на сайте требуют внимания, поскольку имеют доступ к данным страницы. Выход отзывает текущую сессию на сервере; остальные устройства остаются авторизованными.

На сервере сохраняются HMAC номера, замаскированный номер и идентификатор аккаунта. Полный номер используется только для обращения к SMS.ru. Коды и номера не записываются в журналы. Регистрация выполняется только после подтверждения кода. Телефон не появляется в общем рейтинге и списке друзей.

Личный словарь, аватар, серия и статистика на устройстве разделены по идентификаторам аккаунтов. При смене аккаунта страница перезагружается, открытые вкладки также переключаются. Существующие локальные данные Telegram один раз переносятся в пространство первого Telegram-профиля; затем другие Telegram-профили получают отдельное хранилище. Данные гостя автоматически не копируются в новый телефонный аккаунт. Между устройствами словарь пока не синхронизируется. Рейтинг, друзья и игры продолжают храниться на сервере.

SMS-аккаунты не получают Telegram-напоминания, поскольку у них нет подтверждённого Telegram chat ID. Ручная привязка Telegram к телефонному аккаунту в эту версию не входит.

## Ограничения

- Код действует 5 минут; максимум 5 вводов, включая правильный; повторная отправка не чаще раза в минуту.
- Максимум 5 запросов SMS на номер за час, 10 в день и 10 с одного IP за час.
- Максимум 30 проверок кодов с IP за час; общий дневной бюджет отправок задаёт `SMS_DAILY_LIMIT`.
- Лимиты резервируются атомарно в D1; неудачные запросы также расходуют лимит. Это предел числа запросов отправки, а не денежный лимит: тариф зависит от SMS-провайдера.
- Просроченные коды, сессии и лимиты удаляются существующим плановым заданием.

Команда `node --test cloudflare/phone-auth.test.mjs` проверяет создание аккаунтов, повторный вход, разделение номеров, выход, срок жизни, одноразовость и параллельное подтверждение кодов, лимиты, формат номеров и ошибки SMS-провайдера. В тестах SMS.ru заменён имитацией; отправок и списаний нет.
